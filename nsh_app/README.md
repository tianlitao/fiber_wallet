# Fiber Wallet (NSH)

A [Native Shell](https://nsh.dev) (NSH) desktop shell for the Fiber wallet:
the real wallet core (`../core`) with a Rust-drawn Longbridge-style UI on
AppKit.

```sh
export PATH="/Volumes/tlt/.tooling/nsh/bin:$PATH"
cargo run          # AppKit window, debug build; RUST_LOG=debug for verbose logs
nsh run            # same root via the NSH CLI (rebuild+restart on Rust edits)
nsh test           # headless TSX test of the mounted shell
```

## Layout

Icon sidebar with four pages:

- **首页** — total balance (on-chain + channels), stat cards, quick actions
  (收款 / 付款 / Fiber 转账), recent payments and node events.
- **交易** — five tabs: Fiber 转账 (real same-asset keysend: dry-run quote →
  explicit confirm → real send → terminal state), 链上 CKB (on-chain testnet
  transfer with two-step confirmation + broadcast status), 收款 (create
  invoice + QR), 付款 (pay invoice + payment history), 通道 (open/close).
- **发现** — dApp provider host: registry + sandboxed WKWebView running
  `window.fiberWallet` (`src/dapp_host.rs`, `dapp_protocol.rs`,
  `dapp_registry.rs`); writes require default-deny approval dialogs.
- **设置** — theme mode (跟随系统/浅色/深色), accent color (CKB 薄荷 / Fiber 青
  / 极光蓝 / 星紫 / 琥珀), network (测试网/主网 selector — mainnet shown but
  not selectable yet), HTTP(S) proxy, node info, keystore password
  rotation, backup export/import, about.

## Theming

`src/theme.rs` owns a reactive palette (Nervos navy-black dark + light, five
accents) resolved from the config signal plus the system appearance; every
style closure re-reads it, so switches apply live. Type scale is
Longbridge-like (11/12/13/14/16/18/20/28).

## Channels, keystore, backup

- **开通道** (交易 → 通道): lists connected peers (`wallet_list_peers`), opens
  channels by peer pubkey + CKB amount (`wallet_open_channel`, public/private),
  auto-connects by multiaddr when given. Needs a funded funding address
  (testnet faucet) and the peer connected first.
- **Keystore password**: lives in the macOS Keychain (`dev.fiberwallet.nsh`
  / `ckb-key-password` via the `keyring` crate). A legacy `.key-password`
  file is adopted into the Keychain on first run; `FIBER_SECRET_KEY_PASSWORD`
  still overrides. 设置 → 安全 rotates the password: generates a new random
  one and re-encrypts `key`/`sk` in place (`fiber_wallet_core::keystore`),
  node must be stopped.
- **导出 / 导入** (设置 → 导出 / 导入): the whole wallet state (keystore +
  SQLite channel store + manifest) as a gzip-tar encrypted with FNN's
  scrypt+AES format (`fiber_wallet_core::backup`), `.fwexport` suffix.
  Import validates the manifest, backs the current state up to
  `import-backup-<ts>/` and restarts the node. MOVE semantics only: the
  exporting instance must be permanently stopped — one channel state must
  never run under two instances of the same node identity.

## Extras

- **QR codes**: the funding address (首页 hero) and every created invoice
  (交易 → 收款) render as QR on a `canvas`, generated by `fast_qr` and
  re-recorded on theme changes.
- **Title bar**: the system title bar is hidden; the app draws its own
  draggable bar (`window_drag`), leaving macOS traffic lights their space.
- **Toasts** on proxy save, node restart, dApp cards, and close-mode
  validation.
- **Fiber 转账 (Swap tab)**: real Fiber same-asset keysend — a dry-run
  returns a route/fee quote (no HTLC, no payment record), an explicit confirm
  sends the real payment and waits for Fiber's terminal state. Cross-asset
  CKB↔rUSDT is explicitly marked unavailable (no AMM/order-book provider;
  Fiber v0.9.1 routes require one asset end to end).
- **链上 CKB**: builds/signs/broadcasts a testnet transaction from the
  funding lock (ckb-sdk), testnet-only address validation, fee cap re-checked
  after signing; broadcast accepted ≠ confirmed (status query button).
- **Session invoice history**: 收款 keeps the invoices created this session
  (node restarts drop the last one, the list keeps them).
- **Settings → 节点**: open the data directory in Finder.
- **Panic guard**: every bridge operation runs on a thread that turns a
  wallet-core panic into a Failed snapshot + error log instead of a silently
  dead operation.

## Tests

```sh
cargo test --test app                        # headless: probe mounts (fast)
cargo test --test app -- --include-ignored   # full shell mount test
```

Known upstream issue: nsh-testing 0.2.0's headless driver intermittently
never finishes the engine's first commit — even a one-`text` root hangs
`Headless::start` on some runs and passes on the next (the windowed app is
unaffected). The full-shell test is marked `#[ignore]` with details in
`tests/app.rs`.

## Config & proxy

`config.json` under `~/Library/Application Support/FiberWalletNSH/` stores
theme mode, accent, and proxy settings. The proxy is applied to the process
environment (`HTTP_PROXY`/`HTTPS_PROXY`) — effective for CKB RPC HTTP
clients after a node restart (设置 → 代理 → 重启节点生效); P2P is never
proxied.

## Wallet core

`src/bridge.rs` owns a tokio runtime on background threads and calls the real
`fiber_wallet_core` API (`init_local_node`, start/stop/restart, node info,
channels, invoices, payments). Lifecycle uses optimistic phase texts, an
event log, and 10 s polling. Logs stream through `tracing` (the embedded FNN
logs everything).

Data directory: `~/Library/Application Support/FiberWalletNSH/fiber-wallet`
(own directory, so `wallet.lock` never contends with another host). Key
password: `FIBER_SECRET_KEY_PASSWORD` env, else the macOS Keychain
(`dev.fiberwallet.nsh` / `ckb-key-password`); a legacy `.key-password` file
is adopted into the Keychain on first run.
